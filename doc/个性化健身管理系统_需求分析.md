# 个性化健身管理系统需求分析

## 1. 系统目标

本系统面向有健身、塑形、减脂、增肌和提升体能需求的普通用户，提供从身体数据录入、目标推荐、训练计划生成、每日打卡到周期复测调整的一体化服务。系统目标不是简单展示训练视频，而是围绕用户个人身体状态和训练行为，形成一个可执行、可反馈、可持续优化的健身管理闭环。

## 2. 用户闭环流程

用户侧完整流程如下：

```text
录入身体数据
-> 系统推荐可选目标
-> 用户选择重点增强部位和运动偏好
-> 用户设置每周运动时间和提醒
-> 用户填写伤病情况、身体类型和训练限制
-> 用户完成基础体能测试
-> 系统推荐训练计划
-> 用户每日训练并打卡
-> 系统统计完成度、跑步记录、排名和激励信息
-> 用户周期性重新录入身体数据
-> 系统更新评分和后续训练计划
```

## 3. 角色定义

| 角色 | 主要职责 |
|---|---|
| 普通用户 | 录入身体数据、选择目标、执行训练计划、每日打卡、查看身体变化与排名（排名为阶段 5） |
| 管理员 | 管理用户、动作视频、动作标签、打卡统计与榜单统计 |

## 4. 功能需求

### 4.0 功能分期说明

功能按“先闭环、后增强”分期实现，避免一次铺开导致主流程不可用：

| 阶段 | 覆盖的功能条目 |
|---|---|
| 阶段 1（闭环 V1） | 4.1 注册登录、4.2 身体数据录入、4.3 目标推荐与选择、4.4 个性化偏好、4.5 运动时间与提醒、4.6 伤病与训练限制、4.7 体能测试、4.8 训练计划推荐、4.10 每日打卡、4.13 后台管理（用户 / 动作 / 标签 / 打卡统计） |
| 阶段 2 | 4.9 健身动作视频（筛选、跟练、计划关联）、4.12 身体数据复测与计划调整 |
| 阶段 3 | 4.11 中的跑步记录 |
| 阶段 4 | 4.11 中的分享卡片 |
| 阶段 5 | 4.11 中的排行榜 |

阶段 1 结束即形成可演示、可答辩的完整闭环；阶段 2~5 为增强项，任一阶段未完成都不影响系统成立。

### 4.1 用户注册与登录

- 支持手机号或账号密码登录。
- 支持用户基础资料维护。
- 支持密码修改、退出登录和账号安全管理。

### 4.2 身体数据录入

用户首次进入系统时，需要录入基础身体数据，包括：

- 性别
- 年龄
- 身高
- 体重
- 身体类型，如直筒型、梨形、沙漏型、苹果型

系统根据基础数据计算 BMI 等基础指标，并为后续目标推荐和计划生成提供依据。

### 4.3 目标推荐与选择

系统根据用户性别、年龄、身高、体重和身体类型，自动推荐合适的健身目标选项。目标可包括：

- 减脂瘦身
- 增肌塑形
- 提升心肺能力
- 改善体态
- 增强局部力量
- 提升日常体能

用户可以从系统推荐目标中选择一个或多个作为阶段性目标。

### 4.4 个性化偏好设置

用户选择想重点增强或改善的身体部位，例如：

- 腹部
- 腿部
- 臀部
- 手臂
- 背部
- 肩颈
- 全身综合

用户还需要选择喜欢的运动类型，例如：

- 有氧训练
- 力量训练
- 拉伸放松
- 跑步
- HIIT
- 瑜伽或低强度训练

### 4.5 运动时间与提醒设置

用户可选择每周可运动时间：

- 周一到周天分别设置是否训练。
- 可设置每日运动时长，如 10 分钟、20 分钟、30 分钟、45 分钟以上。
- 可选择是否开启训练提醒。
- 可设置提醒时间，帮助用户形成固定训练习惯。

### 4.6 伤病与训练限制

用户需要填写是否存在伤病困扰，例如：

- 膝盖不适
- 腰部不适
- 肩颈不适
- 手腕不适
- 心肺耐力较弱
- 无明显伤病

用户还可选择计划需求和训练限制，例如：

- 小场地
- 零噪音
- 无跳跃
- 不需要器械
- 适合宿舍或居家环境

系统在生成计划时应避开不适合用户身体情况和训练环境的动作。

### 4.7 基础体能测试

系统通过简单问题评估用户当前运动基础，包括：

- 一次可完成俯卧撑个数。
- 一次可完成深蹲个数。
- 一次可完成卷腹个数。
- 上五楼后的身体状态，如轻松、略喘、明显吃力、无法完成。

体能测试结果用于判断计划难度，避免训练强度过低或过高。

### 4.8 训练计划推荐

系统根据身体数据、目标、偏好、每周运动时间、伤病情况、训练限制和体能测试结果，推荐个性化训练计划。

训练计划应包含：

- 计划名称
- 训练周期
- 每周训练天数
- 每日训练内容
- 动作视频列表
- 每个动作的组数、次数或时长
- 休息安排
- 计划适用说明

### 4.9 健身动作视频

- 支持按部位、难度、类型、场景和器械需求筛选动作视频。
- 每个动作视频应包含标题、封面、视频地址、动作说明、训练要点、注意事项和适用人群。
- 计划中的训练动作可直接关联对应视频，方便用户跟练。

### 4.10 每日打卡记录

用户每日完成训练后进行打卡，记录内容包括：

- 完成的训练计划和动作。
- 每个动作完成的组数、次数或时长。
- 跑步距离、配速、用时等跑步数据。
- 当日训练感受或备注。
- 是否完成计划任务。

系统应支持日历形式查看打卡情况和连续打卡天数。

### 4.11 跑步记录、分享与排名（阶段 3~5）

- 用户可记录跑步距离、时间、配速和消耗估算。
- 支持生成跑步记录卡片用于分享。
- 支持按日、周、月查看用户排名。
- 排名可按跑步距离、训练完成次数、连续打卡天数等维度计算。

### 4.12 身体数据复测与计划调整（阶段 2）

用户在训练一段时间后重新录入身体数据。系统根据新旧数据对比：

- 更新身体评分。
- 展示体重、BMI、体型等变化趋势。
- 判断用户是否接近目标。
- 调整后续训练计划难度和内容。

### 4.13 后台管理（阶段 1~5）

后台管理端支持：

- 用户管理（阶段 1）
- 身体数据查看（阶段 1）
- 动作标签管理（阶段 1）
- 打卡数据统计（阶段 1）
- 动作视频管理（阶段 2）
- 推荐记录查看（阶段 2）
- 排行榜数据统计（阶段 5）

说明：不再单独设计“训练计划模板管理”和“推荐规则管理”。训练计划由后端按规则从动作库中筛选生成，规则以代码常量维护，推荐依据写入推荐记录表供管理端查看，避免额外的模板配置与维护成本。

## 5. 非功能需求

### 5.1 性能需求

- 首页计划、今日任务和打卡状态应快速加载。
- 视频列表、排行榜和历史记录应支持分页。
- 热门视频、推荐计划和排行榜可使用缓存提升访问速度。

### 5.2 安全需求

- 用户密码需加密存储。
- 接口需进行身份认证和权限校验。
- 用户身体数据属于隐私信息，应限制非授权访问。
- 重要操作需要记录操作日志。

### 5.3 可用性需求

- 移动端流程应以选择题和快捷输入为主，降低录入成本。
- 今日训练、打卡入口和计划进度应在首页明显展示。
- 训练计划推荐结果需要说明推荐原因，增强用户信任。

### 5.4 可扩展性需求

- 后续可扩展饮食管理、智能穿戴设备接入、AI 私教问答、社区互动等功能。
- 推荐规则和计划模板应支持后台配置。

## 6. 业务规则

1. 用户必须完成基础身体数据录入后，才能获得目标推荐。
2. 用户完成目标、偏好、伤病、时间和体能测试信息后，才能生成完整训练计划。
3. 训练计划应避免推荐与用户伤病情况冲突的动作。
4. 每日打卡必须关联具体训练计划或自由训练记录。
5. 排名数据应基于真实打卡、跑步或训练完成记录计算。
6. 用户复测身体数据后，系统需要重新计算评分并判断是否调整计划。
7. 推荐结果应保留推荐依据，方便后续解释和优化。

## 7. 主要数据对象

| 数据对象 | 对应表 | 说明 |
|---|---|---|
| 用户账号 | `user_account` | 账号、密码散列、昵称、手机号、角色、状态 |
| 用户档案 | `user_profile` | 建档问卷合并表：性别、年龄、身高、体重、体型、主目标与次目标、重点部位、喜欢的运动类型、每周训练日、每日时长、提醒设置、伤病、训练限制 |
| 身体数据 | `body_data` | 身高、体重、BMI、体型、身体评分，可多条，用于复测趋势 |
| 体能测试 | `fitness_test` | 俯卧撑、深蹲、卷腹、爬楼状态、体能等级 L1/L2/L3，可多条 |
| 动作视频 | `exercise` | 动作名称、部位、类型、难度、场景、器械、禁忌标签、视频与封面、要点与注意事项 |
| 动作标签 | `exercise_tag` | 部位 / 类型 / 场景 / 器械 / 难度五类字典，用于筛选与表单选项 |
| 训练计划 | `training_plan` | 名称、目标、难度、每周天数、每次时长、起止日期、状态、推荐依据 |
| 计划明细 | `training_plan_item` | 第几天、动作、组数、次数、时长、休息、完成状态 |
| 打卡记录 | `checkin_record` | 训练日期、是否完成、时长、训练感受、备注 |
| 跑步记录 | `running_record` | 距离、用时、配速、消耗估算、跑步日期（阶段 3） |
| 推荐记录 | `recommend_log` | 推荐输入快照、命中规则、被排除动作数、推荐原因 |

说明：不再设计“排名记录”表，排行榜（阶段 5）直接对打卡记录与跑步记录做聚合统计；也不单独设计目标记录、运动偏好、训练时间、伤病限制四张表，这些属于建档一次性填写的一对一数据，已合并进用户档案表。

## 8. 需求结论

本系统的需求核心是：**用用户身体数据和训练偏好生成个性化计划，再用每日打卡、排名激励和周期复测推动计划持续优化。**

因此，系统设计应优先保证“建档评估、计划推荐、训练执行、激励反馈、复测调整”五个环节的连贯性。阶段 1 的交付目标就是把这五个环节全部打通，激励反馈中的跑步、分享、排名作为阶段 3~5 的增强项后续补齐。
