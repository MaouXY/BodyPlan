# 个性化健身管理系统分阶段实现计划

本文档与《调研环境》《需求分析》《架构设计》配套，用于把已确定的架构拆成可交付的阶段。范围以“先闭环、后增强”为原则，阶段 1 结束即形成可演示、可答辩的完整系统。

> 2026-11-12 演示准备增量：已补目标建议预览、建档/复测原子提交、恢复流程、档案修改、自由打卡、
> 时长/感受/备注、月历、身体变化与历史计划、标签名称修复、异常日志与 SQL 06。
> 当前彩排步骤以 [演示验收清单](演示验收清单.md) 为准，自动验证见 [演示准备验证记录](演示准备验证记录.md)。
> 下文“已完成/已验收”为原阶段的历史记录，不代表本轮已经执行现场彩排。视频、跑步、分享等增强功能尚未交付。

## 1. 交付原则

1. **先闭环、后增强**：阶段 1 打通“建档 → 推荐 → 打卡”，阶段 2~5 只做增强，任一阶段未完成都不影响系统成立。
2. **每个阶段必须有可演示产物**，不允许出现“代码写完了但演示不了”的阶段。
3. **App 端在阶段 1 就要能跑通主流程**，因此阶段 1 的 Android 页面严格控制在 4 个界面，其余页面后置。
4. **已评估的减负项不再回退**：不引入 Redis、不做视频上传、不做提醒推送、不做计划模板表。这些裁剪不影响演示效果，但能显著降低工作量。

## 3. 各阶段明细

### 阶段 0：工程落地（已完成）

- 后端 `BodyPlanApi` 版本对齐模板工程：Spring Boot **3.5.8** + JDK 17。
- 复用 `com.bodyplan.common` 基座：统一返回（`ApiResponse` / `PageResult`）、全局异常处理（`BusinessException` / `ErrorCode` / `GlobalExceptionHandler`）、JWT 鉴权全家桶、MyBatis-Plus 分页、请求日志、Knife4j 接口文档。
- 建表脚本 `BodyPlanApi/sql/01~05`：11 张表 + 标签字典 + 24 个动作 + 演示账号与演示建档数据 + 动作跳跃/噪音属性。
- 三份文档按裁剪后的范围修订（合表、5 字段推荐、分期、去除 Redis 与运营角色）。

**阶段 0 本地验收记录（已完成）**：本地 MySQL 已执行 `01~04` 建库脚本（库 `body_plan`，11 张表、3 个演示账号、
24 个动作、24 条标签、2 份建档与体能数据，中文无乱码）；服务在 `8993` 启动正常，
`/actuator/health` 返回 `UP`、`/doc.html` 可打开、Hikari 正常连接 MySQL。代码已提交为 `阶段 0：工程落地`。

### 阶段 1：闭环 V1（核心交付）——后端 / 管理端 / Android 三端已完成

**阶段 1 后端验收记录（已完成）**：以“膝盖不适 + 宿舍 + 不能跳 + 无器械”的档案走通全链路 ——
注册 → 登录 → 保存建档问卷（`profileCompleted=1`）→ 目标建议 → 体能测试（`L2`）→ 身体数据复测（BMI/评分）→
生成计划（3 天/周、4 动作/天）→ 今日任务 → 打卡成功 → 重复打卡返回 `10502` 幂等提示 → 连续打卡与日历 →
管理端概览 / 用户列表 / 动作库 / 标签字典。计划中禁忌动作（深蹲、开合跳、箭步蹲、波比跳、跳绳、慢跑、哑铃、弹力带）全部被排除，
推荐依据写明“伤病排除 9 个、场地与器械限制排除 3 个”。

**阶段 1 管理端验收记录（已完成）**：`BodyPlanWeb` 类型检查与构建通过（`vue-tsc --noEmit && vite build`），
dev 服务 5174 启动正常，通过 `/api` 代理完成管理员登录、概览、趋势、标签、用户分页调用，未带 token 访问管理端接口返回 401。

**阶段 1 Android 验收记录（已完成）**：`BodyPlanApp` 新增 Retrofit 网络层（`ApiClient` 指向 `http://10.0.2.2:8993/`）、`TokenStore` 登录态、`AppViewModel` 状态机与 4 个界面
（登录注册、5 步建档问卷、我的计划、今日打卡），`assembleDebug` 构建通过，APK 在模拟器上安装并启动成功（Activity 与窗口均创建）。
`BackendFlowTest` 仪器测试在模拟器内跑通：注册 → 登录 → 建档 → 体能测试 → 生成计划（禁忌动作全部排除）→ 今日任务 → 打卡 → 重复打卡拦截，
并在最后一步暴露出两个真实缺陷，已修复并复验：

| 缺陷 | 现象 | 修复 |
|---|---|---|
| 计划明细只排一周 | `endDate` 是 4 周后，但明细只覆盖第一周，第二周起“今日任务”会全空 | `TrainingPlanService` 按 `PLAN_WEEKS` 周循环生成明细（复验：52 条明细 / 12 个训练日，覆盖 2026-09-14 ~ 10-11） |
| 允许对未来训练日打卡 | 打卡记录落到未来日期，连续打卡算成 0、日历失真 | `CheckinService.resolveTrainingDate` 增加未来日期校验，返回新错误码 `CHECKIN_DATE_IN_FUTURE(10504)`（复验：返回“该任务还没到训练日期（2026-09-18），当天再来打卡吧”） |

> 补充：非训练日的「今日任务」返回 `hasTaskToday=false` 与 `nextTrainingDate`，App 侧不会显示打卡按钮，休息日可用自由训练打卡（`planItemId` 为空）记录。

**阶段 1 Android 复验结果（已通过）**：修复后重跑 `gradlew :app:connectedDebugAndroidTest` →
`Starting 2 tests on Medium_Phone(AVD)` / `Finished 2 tests` / **BUILD SUCCESSFUL**，测试报告 `tests=2 failures=0 errors=0`，
其中 `fullClosedLoopWorksOnEmulator` 覆盖：注册 → 登录 → 建档（`profileCompleted=1`）→ 体能测试（L2）→ 生成计划（禁忌动作全部排除、明细覆盖 4 周）→
当前计划 → 今日任务 → 打卡 → 重复打卡拦截（10502）→ 提前打卡拦截（10504）→ 连续打卡 ≥ 1。

四个界面已在模拟器上逐屏截图确认（见 `doc/screenshots/`）：`app-01-登录注册.png`、`app-02-建档问卷.png`（注册成功自动登录后按 `profileCompleted=0` 进入）、
`app-03-我的计划.png`（展示 52 个动作 / 4 周排期与推荐依据）、`app-04-今日打卡.png`（非训练日展示下次训练日与连续打卡 2 天）。

**后端**

- 认证授权：注册、登录、当前用户信息（JWT，角色 `USER` / `ADMIN`）。
- 用户档案：建档问卷读写（身体数据、目标、偏好、每周时间与提醒、伤病与限制），BMI 计算。
- 体能评估：体能测试录入，换算 L1/L2/L3 等级。
- 计划生成：按 5 个字段 + 三步排除法生成计划，写 `training_plan` / `training_plan_item` / `recommend_log`。
- 打卡记录：今日任务、逐项打卡（唯一键防重复）、打卡日历与连续打卡天数。
- 统计：管理端基础统计（用户数、打卡数、动作数）。

**Android（4 个界面）**

- 登录注册页
- 建档问卷页（分步表单）
- 我的计划页（含推荐依据展示）
- 今日打卡页

**Vue 管理端（4 个模块）**

- 用户管理、身体数据查看、动作标签管理、打卡数据统计

**退出条件**：App 上用演示账号完成“注册 → 填写建档问卷 → 生成计划 → 打卡”，管理端能看到该用户与打卡数据。

### 阶段 2：动作视频与复测调整

- 动作视频：列表、按部位/类型/难度/场景/器械筛选、详情（播放或图文要点）、与计划明细关联；管理端动作维护。
- 视频地址先用占位路径，素材到位后替换 `exercise.video_url` / `cover_url` 即可，不改表结构。
- 复测调整：新增 `body_data` 记录、更新评分、展示体重/BMI 变化趋势；复测后按同一套规则重算难度，旧计划置为 `REPLACED`，新计划写入推荐记录。

**退出条件**：能播放跟练动作；复测后计划难度发生变化且推荐依据可查。

### 阶段 3：跑步记录

- 录入手动输入的距离与用时，后端计算配速与消耗估算。
- 历史列表按周/月统计；可关联当日打卡。
- 表已就绪（`running_record`），本阶段只补代码。

### 阶段 4：分享

- 生成跑步/打卡分享卡片（前端渲染或后端出图，二选一，优先前端渲染）。
- 保存分享记录，不做第三方平台真实分享接入。

### 阶段 5：排名

- 日/周/月榜，维度：跑步距离、训练完成次数、连续打卡天数。
- 直接对 `checkin_record` / `running_record` 做聚合查询，不建排名表、不引入 Redis；用户量大时再加索引或缓存。

### 阶段 6：测试与材料

- 后端集成测试：建档 → 生成计划 → 打卡主链路；打卡幂等；权限越权。
- 前端自测：三类页面角色隔离、表单校验、异常提示。
- 演示数据、系统截图、论文与答辩 PPT。

## 6. 风险与兜底

| 风险 | 表现 | 兜底方案 |
|---|---|---|
| Android 环境搭建 | SDK、模拟器、Gradle 下载失败；或模拟器内存不足被系统回收（logcat 出现 `lowmemorykiller: Kill 'com.maou.bodyplanapp'`） | 模拟器内存给到 3GB 以上（`emulator -avd <名字> -memory 3072`），构建前关掉 Android Studio 等占内存进程；真机演示前统一局域网与固定 IP |
| 视频素材缺失 | 找不到可用素材 | 保持占位路径 + 图文要点，功能位不删；素材到位后只改数据 |
| 时间不足 | 阶段 2 及之后未完成 | 阶段 1 已是完整毕设，直接在阶段 1 范围内答辩 |
| 联调不通 | 真机/模拟器访问不到后端 | 模拟器固定 `10.0.2.2`，真机用局域网 IP，放行防火墙 8993 |
| 推荐结果不合理 | 选出的动作强度不匹配 | 调整 `exercise` 的标签与难度、规则常量阈值，不改代码结构 |

## 7. 答辩演示路径（阶段 1 版本）

1. App 注册并登录。
2. 填写建档问卷：身体数据 → 目标 → 偏好 → 每周时间 → 伤病与限制 → 体能测试。
3. 系统推荐目标，用户确认。
4. 生成训练计划，展示“推荐依据”（命中的规则、因膝伤与宿舍限制被排除的动作数）。
5. 今日任务逐项打卡，展示打卡日历与连续打卡天数。
6. 管理端查看用户列表、身体数据、动作标签与打卡统计。

阶段 2~5 完成后，演示路径延伸为：跟练动作视频 → 周期复测并自动调整计划 → 记录跑步 → 生成分享卡片 → 查看排行榜。
