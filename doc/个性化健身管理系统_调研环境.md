# 个性化健身管理系统调研环境

## 1. 项目背景

随着移动互联网、智能手机和运动健康设备的发展，用户对健身应用的需求已经不再停留在“看视频跟练”或“简单记录步数”的阶段，而是希望系统能够根据个人身体状态、训练目标、运动偏好和可支配时间，自动推荐更合适的训练计划，并在执行过程中持续记录、反馈和调整。

本课题拟设计并实现一套基于 Spring Boot + Vue + Android 的个性化健身管理系统。系统整体目标类似 Keep 类健身应用，但在课程设计阶段重点聚焦“个性化计划闭环”：用户录入身体数据，系统推荐目标和训练计划，用户每日打卡，系统根据训练记录和复测数据持续优化计划，使用户逐步接近自己的健身目标。

## 2. 调研目标

本阶段调研主要围绕以下问题展开：

1. 健身类应用如何完成从用户建档到训练计划推荐的流程。
2. 用户在制定计划前需要录入哪些身体数据和运动偏好。
3. 系统如何通过打卡、排行榜和分享形成每日激励。
4. 身体数据复测如何反向影响后续训练计划。
5. Spring Boot + Vue + Android 技术组合是否能够支撑该业务闭环。

## 3. 用户使用场景调研

面向普通健身用户，系统应覆盖以下典型场景：

| 场景 | 用户行为 | 系统响应 |
|---|---|---|
| 初次使用 | 录入性别、年龄、身高、体重等基础数据 | 建立用户身体档案并计算基础指标 |
| 选择目标 | 查看系统推荐的减脂、塑形、增肌、提升体能等目标 | 根据身体数据推荐更适合的目标选项 |
| 完善偏好 | 选择重点增强部位、喜欢的运动类型、每周运动时间 | 形成个性化训练画像 |
| 风险控制 | 填写伤病困扰、身体类型、训练限制 | 避免推荐不适合的动作和计划 |
| 体能测试 | 填写俯卧撑、深蹲、卷腹、上五楼状态等指标 | 判断用户当前运动基础 |
| 计划执行 | 按每日计划完成训练并打卡 | 记录组数、次数、距离、完成度 |
| 激励反馈 | 分享跑步记录、查看排名 | 提升用户持续训练动力 |
| 周期复测 | 重新录入身材和身体数据 | 更新评分并调整后续计划 |

## 4. 同类产品功能归纳

参考 Keep 类应用和常见运动健康产品，可以归纳出以下共性功能：

1. 用户身体档案：性别、年龄、身高、体重、体型、训练基础等。
2. 目标推荐：根据身体数据推荐减脂、塑形、增肌、提升心肺等方向。
3. 计划制定：结合训练目标、运动偏好、可训练时间和伤病限制生成计划。
4. 动作视频：通过视频降低动作学习成本，展示动作要点和注意事项。
5. 每日打卡：记录训练是否完成，以及组数、次数、跑步距离等细节。
6. 数据反馈：通过评分、趋势图、完成率和排名展示训练效果。
7. 激励机制：通过提醒、排行榜、分享、连续打卡等方式提升用户留存。

## 5. 技术调研环境

### 5.1 前端与移动端

- Vue 3：用于后台管理端，适合实现用户管理、视频管理、训练计划模板管理和数据统计。
- Android：用于用户移动端，承载身体数据录入、计划查看、每日打卡、跑步记录、提醒和分享等高频操作。
- 前后端分离：移动端、管理端和服务端通过 REST API 交互，便于独立开发和维护。

### 5.2 后端与数据层

- Spring Boot 3.5.8（JDK 17）：作为后端主体框架，负责认证授权、用户档案、身体评分、计划推荐、打卡记录和数据统计；版本与既有模板工程保持一致，可直接复用统一返回结构、全局异常处理、JWT 鉴权、MyBatis-Plus 分页和接口文档基建。
- MySQL 8.x：存储用户账号、用户档案、身体数据、体能测试、动作视频、训练计划、打卡记录和跑步记录等核心业务数据。
- 不引入 Redis：排行榜与统计均通过 MySQL 聚合查询实现，课程设计规模的数据量不需要额外中间件，可减少部署与答辩解释成本。

### 5.3 开发与部署环境

- 开发工具：IntelliJ IDEA、VS Code、Android Studio。
- Java 环境：JDK 17。
- 数据库环境：MySQL 8.x。
- 前端环境：Node.js 18+。
- 部署环境：Linux + Nginx + Spring Boot 应用进程。

## 6. 业务闭环结论

本系统的核心闭环可以概括为：

```text
身体数据录入
-> 目标与偏好选择
-> 体能与限制评估
-> 推荐训练计划
-> 每日打卡与训练记录
-> 排名、分享和提醒激励
-> 周期复测身体数据
-> 调整评分和后续计划
-> 持续接近目标
```

该闭环能够覆盖用户从首次建档到长期训练管理的完整路径，符合个性化健身管理系统的设计目标。

## 7. 调研输出

本阶段调研确定系统应围绕“身体数据 + 个性化计划 + 每日打卡 + 复测调整”展开。后续需求分析和架构设计应重点保证以下能力：

- 能够采集足够完整的用户身体与偏好数据。
- 能够根据数据推荐合理目标和训练计划。
- 能够记录用户每日训练完成情况。
- 能够通过提醒、排名和分享提升用户坚持度。
- 能够根据复测数据持续调整计划，形成长期闭环。
