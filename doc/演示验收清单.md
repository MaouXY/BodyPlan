App 界面已更新为中文健身应用，桌面名称为“律动健身”，对应 BodyPlan 项目，包名仍为 `com.maou.bodyplanapp`。底部入口为“今日、计划、我的”；登录页不再预填或展示演示凭据，请使用第 4 节的账号。主页面只展示中文计划摘要，完整算法依据保留在后端接口 `GET /api/v1/plans/current/reason`，不作为面向用户的长段说明展示。

## 1. 本轮交付与验收边界

已实现：

- 目标建议直接根据问卷当前身体数据预览，不要求先建档，不产生身体历史记录。
- 建档或复测统一提交档案、身体历史、体能测试和新计划，服务端失败统一回滚；旧计划保留为已替换。
- 已建档但缺少体能测试的旧账号重新登录后返回问卷，已有字段回填。
- App 新增“我的档案”：修改档案/复测、身体变化记录、与上次体重/BMI 对比、历史计划状态。
- App 支持非训练日自由打卡、实际时长、训练感受、备注、撤销与重新打卡。
- App 支持月历切换、每月活跃天数/次数、最近 100 条打卡记录。
- 数据加载失败显示错误并保留旧快照，不再假装“没有计划”；请求期间阻止重复提交。
- 标签列表使用数据库名称；异常保留场景、上下文、堆栈；后端运行日志写入文件。
- 真机服务地址可通过 Gradle 参数配置；新增演示账号与动态日期 SQL。

本次不执行数据库脚本、不代做现场彩排。视频播放/动作维护页面、跑步、分享、用户端综合排行榜仍属于后续增强范围，不纳入此次验收。训练时间只记录偏好，不发送推送通知。仅修改体重不保证体能等级改变，等级由体能测试计算。

脚本中的演示 ID 范围为专用保留范围；若库中已有同 ID 的非演示数据，先检查并调整整套演示 ID，不能直接覆盖。

MySQL 命令行示例（先登录，再输入 source；不是 PowerShell 重定向）：

```text
mysql --default-character-set=utf8mb4 -uroot -p
source F:/javaWeb/毕设接单/BodyPlan/BodyPlanApi/sql/06_demo_acceptance_data.sql
```

执行结束自带查询。首次执行预期：

| 核对项 | 预期 |
| --- | --- |
| 专用账号 | demo_ready、demo_new、demo_compare 共 3 个 |
| demo_ready 计划 | 一条 ACTIVE 演示计划，日期覆盖执行当天 |
| 演示计划明细 | 56 条，4 周，每天 2 个动作 |
| 历史打卡 | demo_ready 14 条，demo_compare 7 条，均为过去日期 |
| 今天 | 未预填打卡，留给现场操作 |
| 身体历史 | 两个已建档专用账号各 3 条 |

预置计划、身体评分和历史记录是明确标注的演示样例，不是算法计算结果。算法验收必须使用新账号建档或修改档案/复测后的计划。
首次执行若不是当天，近期趋势与连续天数会随时间自然变化；重新执行脚本不会重置。可在 App 生成新计划，并进行自由训练打卡。

## 3. 启动准备

### 后端

在 `F:\javaWeb\毕设接单\BodyPlan\BodyPlanApi` 打开 PowerShell：

```powershell
mvn spring-boot:run
```

数据库配置来自 `APP_DB_URL`、`APP_DB_USERNAME`、`APP_DB_PASSWORD`，未设置时使用项目现有本地默认值。

- [ ] 打开 `http://127.0.0.1:8993/actuator/health`，显示 `UP`。
- [ ] 打开 `http://127.0.0.1:8993/doc.html`，接口文档可见。
- [ ] `logs/bodyplan-api.log` 有启动日志，中文可读。

### 管理端

在 `F:\javaWeb\毕设接单\BodyPlan\BodyPlanWeb` 执行：

```powershell
npm run dev -- --port 5174 --strictPort
```

依赖缺失时先运行 `npm install`。浏览器打开 `http://127.0.0.1:5174`。
端口占用时换一个未占用端口，以终端实际地址为准；后端仍使用 8993。

### Android

Android Studio 首次打开时选择 `BodyPlanApp` 目录，并完成一次 Gradle 同步：

1. 本机 SDK 路径为 `D:\Android\Sdk`，项目 `local.properties` 的 `sdk.dir` 应指向该目录；换机器时按实际安装位置调整。
2. 项目编译使用 API 37，本机平台文件位于 `D:\Android\Sdk\platforms\android-37.0`。仅有 API 36.1 的 IDE SDK 关联不足以匹配当前编译配置。
3. 按 `Ctrl+Shift+A`，搜索并执行 `Sync Project with Gradle Files`，等待同步完成。首次同步可能下载 Gradle 源码包，在底部 Build 的 Sync 页签查看进度。
4. 若运行配置提示 `Please select Android SDK`，先核对 SDK 路径并执行上述同步，再重新打开运行配置检查。命令行构建通过不能代替 IDE 模型同步。

若提示 `Emulator failed to connect within 5 minutes`，随后又提示 `Medium Phone is already running`，先检查设备是否离线：

```powershell
& D:\Android\Sdk\platform-tools\adb.exe devices -l
```

本机在 2026-11-13 出现旧快照恢复后持续 `offline`，关闭卡住的实例、跳过快照冷启动后恢复正常，应用和设备数据保留。`Medium Phone` 已设置默认冷启动。再次遇到时先停止该模拟器，再从 Device Manager 执行 Cold Boot；不要连续重复启动同一设备，也不要直接清除设备数据。

开机完成判据：ADB 列表中设备状态为 `device`，且以下命令输出 `1`，然后再运行 App：

```powershell
& D:\Android\Sdk\platform-tools\adb.exe -s emulator-5554 shell getprop sys.boot_completed
```

设备序列号以 `adb devices -l` 的实际结果为准。

在 `F:\javaWeb\毕设接单\BodyPlan\BodyPlanApp` 构建：

```powershell
.\gradlew.bat --no-daemon :app:assembleDebug
```

默认 APK 使用模拟器地址 `http://10.0.2.2:8993/`。
产物：`app/build/outputs/apk/debug/app-debug.apk`。
用 Android Studio 安装运行，或在只有一个已连接设备时执行：

```powershell
& D:\Android\Sdk\platform-tools\adb.exe install -r .\app\build\outputs\apk\debug\app-debug.apk
```

真机与电脑接入同一局域网，允许电脑防火墙访问 8993，重新构建：

```powershell
.\gradlew.bat --no-daemon :app:assembleDebug "-PbodyplanApiUrl=http://192.168.1.10:8993/"
```

IP 换成电脑实际地址，末尾 `/` 保留。重新安装 APK。真机登录页的后端地址必须与电脑 IP 一致，不能仍是 `10.0.2.2`。
返回模拟器时不传 `bodyplanApiUrl` 再构建。不要为了修演示更改电脑日期。
