# 新增需求第一版

日期：2026-11-15。

## 范围

- 运动：跑步、步行、骑行、室内力量；可选目标距离、目标配速，距离达标可自动结束。GPS 路线、暂停、结束、本地草稿、补传、历史详情独立于每日自由打卡。
- 教练：管理员创建教练、分配学员；教练查看所辖学员当日计划任务并发送站内提醒；用户在 App 内查看、标记已读。不包含关闭 App 后的厂商推送。
- 饮食：基础食物库、按餐次与克数记录、修改删除、营养合计、按日期保存可编辑目标。所有营养值均是估算，不提供医疗建议。

## 实现约定

- 保持 Spring Boot / Vue / Jetpack Compose 现有技术栈。
- 运动路线使用 WGS84 GPS 坐标与 Leaflet / OpenStreetMap 底图；不内置付费地图密钥，不生成虚构实跑路线。
- 轨迹仅本人可读，教练只看摘要。地点跳变、长时间失联与暂停之间不计算连线距离。
- 新表与示例数据放在 `BodyPlanApi/sql/08_wellness_modules.sql`，可重复执行，不删除旧业务数据。
- 用户已授权本轮独立执行 SQL。执行前检查数据库与已有表，不重置现有账号、计划或打卡。
- 每个阶段 Git 提交留档；测试、执行情况与尚需真机验证的限制在验收文档中如实记录。

## 本轮验证与修正

- 后端全量 40 项测试通过，含 9 项实库事务回滚集成测试。
- Android 单元测试 20 项通过；模拟器最终整组 15 项通过，0 失败、0 跳过。
- 原有 2GB 模拟器出现低内存回收，独立创建 4GB 无窗口测试模拟器，不更改原设备。
- 截图检查发现地图 DOM 存在但容器为 0 高；改用 WebView 实际视口像素初始化并响应尺寸变化，底图、路线与起终点均已截图确认，并增加路线像素断言。
- 小步移动保留上个有效锚点，避免慢走连续小于 3 米时被全部过滤。
- 页面请求串行处理，账号切换取消旧请求；运动目标取消恢复修改前的配置。
- 精确路线只向本人提供；禁用、删除或角色变化的账号不能继续使用旧令牌。
- 代码与操作验收见 `doc/新增功能验收说明.md`。
